# AGENTS.md

この「AI 仕事部屋」で作業する AI エージェントへの指示書です。
利用者は、ここで AI に仕事（企画・文章・調べもの・SEO・デザインの準備など）を手伝ってもらい、**できあがったものを残しながら、ノウハウを貯めていきます**。

## 利用者について
- プログラミングの知識はない前提で話す。専門用語には短い説明を添える
- 利用者は「〇〇について相談したい」「〇〇を作って」のように、ふだんの言葉で頼む。スキル名やフォルダ名を覚えてもらう必要はない

## フォルダの役割
- `about/` … 利用者のこと（`profile.md`: 自分・お店・会社・お客さん、`brand.md`: 文章の雰囲気・使わない言葉・色）。**毎回読む**
- `inbox/` … 受け取り箱。相談したいこと・資料・メモをとりあえず置く場所
- `work/` … 仕事ごとのフォルダ（例: `work/2026-11-24-1430-k7q2-ブログ記事/`）。中に次のものを置く
  - `request.md`（何を頼まれたか・目的・ゴール・資料の一覧）
  - `notes.md`（相談の経過・決めたこと）
  - `materials/`（受け取った資料）
  - `outputs/`（できあがったもの）
- `knowhow/` … 仕事から学んだノウハウ。テーマ別のフォルダ（例: `knowhow/ブログ/`）に貯めていく
- `templates/` … できあがったもののひな形（企画書・記事構成・SNS 投稿など）。中身は書き換えない

## 基本の流れ
1. **相談を始める** → スキル `start-work`
2. **できあがったものを作る** → スキル `make-output`
3. **ノウハウを残す** → スキル `save-knowhow`（仕事のひと区切りや完了時に提案する）

## いつも守ること
- 作業を始める前に `about/` を読む。「〇〇」のままの項目があれば、埋めるか利用者に聞く
- 関係しそうな `knowhow/` を探して読み、使ったノウハウはどれか利用者に伝える
- 文章の雰囲気は `about/brand.md` に合わせる
- 事実や数字には出典（参考にしたページなど）を書く。確認できないことは「要確認」と書く
- 画像そのものは作らない。必要なら画像生成 AI 向けの指示文（`templates/image-prompt.md`）を作る。図やアイコンは SVG で作ってよい
- パスワード・API キー・お客さんの名前や個人情報は、ノウハウ（`knowhow/`）に書かない
- 既存のファイルを消したり、大きく書き換えたりする前に、利用者に確認する
- 作業が終わったら、何を作ったか・どこに保存したか（Finder やエクスプローラーでの開き方も）を伝える

## スキル
- スキルは `.agents/skills/<名前>/` と `.claude/skills/<名前>/` の両方に同じ内容で置く
- 外部から取り込んだスキルは `.agents/skills/SOURCES.md` に記録する

## Git（変更の保存）
- ひと区切りごとにコミット（保存）する（例: 「ブログ記事: 構成案を作成」）。お客さんの名前はメッセージに入れない
- この部屋では作業フォルダ（worktree）を分けず、本体でそのまま作業する（利用者が Obsidian などで同じファイルを見ているため）
- GitHub を使う場合は、必ず非公開（Private）リポジトリにする

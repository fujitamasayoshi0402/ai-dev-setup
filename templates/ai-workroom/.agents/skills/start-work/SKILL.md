# 相談を始める

利用者はプログラミングの知識がない前提で、ふだんの言葉で話す。

## 手順

1. **利用者のことを読む**。`about/profile.md` と `about/brand.md` を読む
   - 「〇〇」のままの項目が多ければ、先に一緒に埋めるか聞く（埋めなくても相談は進めてよい）
2. **過去のノウハウを探す**。`knowhow/` からファイル名・見出しで関係しそうなものを探して読む。使えそうなものがあれば、どのファイルかを利用者に伝える
3. **受け取り箱を見る**。`inbox/` に関係しそうな資料があれば読む
4. **新しい仕事か、続きかを確認する**。`work/` に似た仕事があれば、その続きかどうかを利用者に聞く
   - **続きの場合**: その仕事の `request.md` と `notes.md` を読み、これまでの流れを3行で伝える。新しい資料があれば `materials/` に移して `request.md` の「資料」に追記する。**新しいフォルダは作らず、`request.md`・`notes.md` も作り直さない**。手順7へ進む
   - **新しい仕事の場合**: 手順5へ進む
5. **相談内容を整理する**。次の4つがわからなければ、**1つずつ**質問する
   - 何のためにやるか（目的）
   - 何ができたら終わりか（ゴール。どんなものを作るか）
   - 期限・予算・使えるもの
   - 誰に向けたものか
6. **仕事のフォルダを作る**。名前は `work/YYYY-MM-DD-HHMM-xxxx-テーマ/`
   - `YYYY-MM-DD-HHMM` は作った**日付と時刻**、`xxxx` は**英小文字と数字のランダムな4文字**（例: `work/2026-11-24-1430-k7q2-ブログ記事/`）。`YYYY-MM-DD-HHMM-xxxx` の部分を「仕事 ID」と呼ぶ
   - `テーマ` は短い日本語。**お客さんの名前は入れない**（フォルダ名はノウハウの出典として使われるため）。**空白も入れない**
   - `request.md` … `templates/request.md` の形で、手順5の内容と仕事 ID を書く。お客さんの名前などは、このファイルの中にだけ書く
   - `notes.md` … `templates/notes.md` の形で作る
   - `materials/` … 資料を入れるフォルダ。使った `inbox/` の資料は、利用者に確認してからここに移し、`request.md` の「資料」に**ファイルの場所と、何が書いてあるか**を1行ずつ書く
   - `outputs/` … できあがったものを入れるフォルダ
7. **相談を進める**。決まったこと・やめた案とその理由・まだ決まっていないことは、その都度 `notes.md` に書き足す
8. **次の一歩を提案する**
   - 何かを作る段階になったら → スキル `make-output`
   - ひと区切りついたら → スキル `save-knowhow` でノウハウを残すことを提案する

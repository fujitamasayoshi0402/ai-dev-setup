# ノウハウを残す

## 手順

1. **材料を読む**。その仕事の `notes.md`・`request.md`・`outputs/`・`materials/`
2. **次にも使えるノウハウを抜き出す**。たとえば次のようなもの
   - うまくいったやり方・手順
   - 判断の基準（なぜその案を選んだか）
   - うまくいかなかったこと・やめた案とその理由
   - チェックリストにできること
   - 新しく覚えた言葉とその意味
3. **一般的な形に直す**。お客さんの名前・個人情報・社外秘の数字・パスワードなどは書かない。必要なら「〇〇業のお客さん」のように書き直す
4. **置き場所を決める**
   - テーマを決める（例: `knowhow/ブログ/`、`knowhow/SNS/`、`knowhow/デザイン/`）。フォルダがなければ作る
   - 同じ内容のファイルがすでにあれば、新しく作らずに**書き足す**。食い違う内容があれば、どちらが正しいか利用者に確認する
   - 新しく作る場合は `templates/knowhow.md` の形にする。ファイル名は内容がわかる短い日本語（例: `knowhow/ブログ/タイトルのつけ方.md`）
5. **出典を書く**。「出典」には、**仕事 ID（`YYYY-MM-DD-HHMM-xxxx`）だけ**を書く。フォルダ名のテーマ部分やお客さんの名前は書かない
6. **最終版を見せる**。出典も含めて、保存する内容をそのまま利用者に見せる。お客さんを特定できる情報が残っていないかも一緒に確認し、了承を得てから保存する
7. **コミット（保存）する**。メッセージは「ノウハウ: 〇〇 を追加」のようにする（お客さんの名前は入れない）

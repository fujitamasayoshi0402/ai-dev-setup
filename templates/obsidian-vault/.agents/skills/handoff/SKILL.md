# 作業を引き継ぐ

複数のエージェントを使い分けるときや、利用枠の上限で別のエージェントに切り替えるときに使う。

## 引き継ぐ側（メモを作る）

1. 作業中の変更があれば、「作業途中: 〇〇」のようなメッセージでコミットする
   - そのフォルダの `AGENTS.md` の Git のルールに従う。今のブランチが `main` で、ルールが `main` への直接コミットを禁じている場合は、コミットする前に利用者に確認する
   - 利用者が望まない場合は、コミットせずにその旨をメモに書く
2. 作業フォルダのルートに `HANDOFF.md` を作る（すでにあれば上書きする）。形式は下のとおり
3. 利用者に次のことを伝える
   - 作業フォルダの場所（フルパス）。**受け取る側のエージェントは、この同じフォルダで起動する必要がある**（`HANDOFF.md` は Git で管理していないので、別の worktree やフォルダからは見えない）
   - 受け取る側への頼み方（「HANDOFF.md を読んで、作業の続きをして」）

```markdown
# 引き継ぎメモ

- 作成日時: YYYY-MM-DD HH:MM
- 作成したエージェント: 〇〇
- 作業フォルダ: 〇〇（フルパス）
- ブランチ: 〇〇 / 最新のコミット: 〇〇

## 目的
（利用者が最終的にやりたいこと）

## やったこと
- 

## 次にやること（優先順）
1. 

## 決まったこと・利用者の好み
- （利用者と決めた方針、言われたこと）

## 注意点・未解決の問題
- （うまくいかなかったこと、触ってはいけないところ、エラーの内容）

## 関係するファイル
- 
```

- 受け取る側は会話の履歴を見られないので、**利用者と決めたことや言われたこと**を必ず書く
- 推測で書かない。確認できていないことは「未確認」と書く
- パスワード・API キー・トークンなどの秘密情報は書かない（必要なら「`.env` の〇〇を使う」のように場所だけ書く）

## 受け取る側（メモを読んで続ける）

1. `HANDOFF.md` を読む。あわせて `git log -5` と `git status` で、メモと実際の状態が合っているか確認する
2. 「次にやること」と注意点を、利用者に短く確認してから作業を始める
3. メモと実際の状態が食い違っていたら、作業を始める前に利用者に伝える

`HANDOFF.md` がない場合は、次の順に確認して前の作業内容を整理し、利用者に伝える。

1. `git status --short` … 新しく作られたファイル（未追跡）を含め、変更のあるファイルをすべて把握する
2. `git log -5` … 最近のコミット
3. `git diff` … まだステージしていない変更
4. `git diff --cached` … ステージ済み（コミット予定）の変更
5. 未追跡の新しいファイルは、中身を直接読んで確認する

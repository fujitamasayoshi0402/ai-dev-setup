# 知見を貯める

## 手順

1. **材料を読む**。対象の案件の `notes.md`・`brief.md`・`outputs/`・`materials/`
2. **次にも使える知見を抜き出す**。たとえば次のようなもの
   - うまくいったやり方・手順
   - 判断の基準（なぜその案を選んだか）
   - 失敗したこと・見送った案とその理由
   - チェックリストにできること
   - 新しく覚えた用語とその意味
3. **一般化する**。お客さんの名前・個人情報・社外秘の数字・パスワードなどは書かない。必要なら「〇〇業のお客さん」のように一般的な形に書き直す
4. **置き場所を決める**
   - テーマを決める（例: `seo/`、`branding/`、`design/`、`writing/`）。フォルダがなければ作る
   - 同じ内容のファイルがすでにあれば、新しく作らずに**追記**する。食い違う内容があれば、どちらが正しいか利用者に確認する
   - 新しく作る場合は `90_templates/knowledge.md` の形にする。ファイル名は内容がわかる短い日本語（例: `seo/タイトルのつけ方.md`）
5. **出典を書く**。知見の「出典・関係する案件」には、**案件 ID（`YYYY-MM-DD-HHMM`）だけ**を書く。フォルダ名のテーマ部分やお客さんの名前は書かない
6. **最終版を利用者に見せる**。出典を含めて、保存する内容をそのまま見せる。お客さんを特定できる情報が残っていないかも一緒に確認し、了承を得てから保存する
7. **コミットする**。メッセージは「知見: 〇〇 を追加」のようにする（お客さんの名前は入れない）

# 相談を始める

## 手順

1. **前提を読む**。`10_context/profile.md` と `10_context/brand.md` を読む
   - 「〇〇」のままの項目が多ければ、先に一緒に埋めるか利用者に聞く（埋めなくても相談は進めてよい）
2. **過去の知見を探す**。`20_knowledge/` からファイル名・見出し・タグで関係しそうなものを探して読む
   - 使えそうな知見があれば、どのファイルかを利用者に伝える
3. **資料を確認する**。`00_inbox/` に関係しそうな資料があれば読む
4. **相談内容を整理する**。次の4点がわからなければ、**1つずつ**質問する
   - 目的（何のためにやるか）
   - ゴール（どんな成果物ができたら終わりか）
   - 前提・制約（期限・予算・使えるもの）
   - 誰に向けたものか
5. **既存の案件か確認する**。`30_projects/` に似た案件があれば、その続きか、新しい案件かを利用者に聞く。続きなら、その案件フォルダで手順6へ進む
6. **新しい案件フォルダを作る**。名前は `30_projects/YYYY-MM-NN-テーマ/`
   - `NN` はその月の通し番号（`01`、`02`…）。同じ月の既存フォルダを見て、重ならない番号にする
   - `テーマ` は内容がわかる短い日本語（例: `2026-11-01-サイト改善`）。**お客さんの名前は入れない**（フォルダ名は知見の出典として使われるため）。**空白も入れない**
   - `YYYY-MM-NN` の部分を「案件 ID」と呼ぶ
   - `brief.md` … `90_templates/project-brief.md` の形で、手順4の内容を書く。お客さんの名前などは、この中にだけ書く
   - `notes.md` … `90_templates/project-notes.md` の形で作る
   - `outputs/` … 成果物を入れるフォルダ
   - `materials/` … 資料を入れるフォルダ。使った `00_inbox/` の資料は、利用者に確認してからここに移し、`brief.md` の「資料」に**ファイルの場所と、何が書いてあるか**を1行ずつ書く
7. **相談を進める**。決まったこと・見送った案と理由・未解決のことは、その都度 `notes.md` に追記する
8. **次の一歩を提案する**
   - 成果物が必要になったら → スキル `make-deliverable`
   - 区切りがついたら → スキル `harvest-knowledge` で知見を貯めることを提案する

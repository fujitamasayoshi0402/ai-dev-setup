# 作業を引き継ぐ

複数のエージェントを使い分けるときや、利用枠の上限で別のエージェントに切り替えるときに使う。

## 引き継ぐ側（メモを作る）

1. 作業中の変更があれば、「作業途中: 〇〇」のようなメッセージでコミットする（利用者が望まない場合は、コミットせずにその旨をメモに書く）
2. 作業フォルダのルートに `HANDOFF.md` を作る（すでにあれば上書きする）。形式は下のとおり
3. 利用者に、受け取る側への頼み方（「HANDOFF.md を読んで、作業の続きをして」）を伝える

```markdown
# 引き継ぎメモ

- 作成日時: YYYY-MM-DD HH:MM
- 作成したエージェント: 〇〇
- ブランチ: 〇〇 / 最新のコミット: 〇〇

## 目的
（利用者が最終的にやりたいこと）

## やったこと
- 

## 次にやること（優先順）
1. 

## 決まったこと・利用者の好み
- （利用者と決めた方針、言われたこと）

## 注意点・未解決の問題
- （うまくいかなかったこと、触ってはいけないところ、エラーの内容）

## 関係するファイル
- 
```

- 受け取る側は会話の履歴を見られないので、**利用者と決めたことや言われたこと**を必ず書く
- 推測で書かない。確認できていないことは「未確認」と書く

## 受け取る側（メモを読んで続ける）

1. `HANDOFF.md` を読む。あわせて `git log -5` と `git status` で、メモと実際の状態が合っているか確認する
2. 「次にやること」と注意点を、利用者に短く確認してから作業を始める
3. メモと実際の状態が食い違っていたら、作業を始める前に利用者に伝える

`HANDOFF.md` がない場合は、`git log` と `git diff` から前の作業内容を整理して利用者に伝える。
